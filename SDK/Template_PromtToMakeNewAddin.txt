Разработать плагин MagicAreaUpdater
**Общие требования к коду:**
-плагин для Autodesk Revit 2022 
- Не использовать логирование в debug.
- Не использовать XML-суммари (`summary`) в документации.
- Разделять код на регионы (`#region`) для удобства чтения и поддержки.
- Перед каждым публичным методом добавлять краткий комментарий на русском, описывающий его назначение.
- В начале каждого создаваемого или изменяемого класса добавлять краткий комментарий на английском, поясняющий его назначение.
- Тщательно проверять код на отсутствие ошибок.
- Убедиться, что код не содержит ошибок и соответствует описанным требованиям.
- Использовать понятные имена для классов, методов и переменных, отражающие их назначение.
- Соблюдать принцип единственной ответственности (SRP) для каждого класса и сервиса.
- Избегать избыточных комментариев, но обеспечивать ясность кода через структуру и краткие пояснения.
- при разработке UI используй файл "Стандарт UI".
- Все сообщения, в том числе в том числе TaskDialog, бери из статичного класса
- Для постоянных данных (текст, ссылки, другое) сделай статичный класс, в котором будет это все храниться. 
##Важно:
• Архитектура должна быть модульной — каждая команда отдельный класс.
• Код должен быть надёжным: без падений Revit, с обработкой ошибок и пустых случаев.
• По возможности вынести общие части (парсинг текста, форматирование информации) в отдельный статический класс-утилиту.
• Код должен быть максимально чистым, соответствовать Revit API best practices.
## Функционал
Для элементов категорий BuiltInCategory.OST_Ceilings, BuiltInCategory.OST_Floors, BuiltInCategory.OST_Walls, BuiltInCategory.OST_Roofs нужно сделать плагин по обновлению параметра экземпляра "ADSK_Размер_Площадь". 
Нужно подписать плагин на событие DocumentChanged Event, получать от него DocumentChangedEventArgs Class. У них вызывать методы GetAddedElementIds и GetModifiedElementIds Method (в них передавать ElementFilter, который работает только с этими категориями). Если добавленные или измененые элементы из списка категорий, то смотрим, изменилась ли площадь HOST_AREA_COMPUTED. Если значение параметра HOST_AREA_COMPUTED изменилось (и если оно не null и не =0) или если значение парамтера HOST_AREA_COMPUTED не равно значению параметра "ADSK_Размер_Площадь", то записываем в параметр "ADSK_Размер_Площадь" значение из HOST_AREA_COMPUTED (у этого параметра StorafeType Double). Если значение параметра HOST_AREA_COMPUTED null или =0, то в параметр "ADSK_Размер_Площадь" записываем 0.
Процесс обновления значения параметра надо обернуть в транзакцию.
Если у экземпляра нет параметра "ADSK_Размер_Площадь" - ошибку пропускать (далее разработаю модуль для добавления этого параметра в проект из файла ФОП).
Сделать кнопку для открытия окна настроек (WPF окно, стиль оформления сделать как у приложенного текстового файла). В настройках будут указаны категории (BuiltInCategory.OST_Ceilings, BuiltInCategory.OST_Floors, BuiltInCategory.OST_Walls, BuiltInCategory.OST_Roofs) и напротив них - галочки. Если галочка включена - значение для этой категории обновлять. Настройки хранить в папке 
C:\Users\Dementev\AppData\Roaming\MagicEntry\UserData\MagicAreaUpdater
Соответственно, при загрузке нового Revit надо читать файл настроек и применять их.
